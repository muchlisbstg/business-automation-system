## Status semantics

- `NOT_INSTALLED`: registry/control artifact not present.
- `NOT_EVALUATED`: repository has not completed its evidence-based evaluation.
- `NOT_VERIFIED`: evidence has not yet been collected or independently checked.
- `PARTIAL`: only explicitly evidenced controls are implemented.
- `IMPLEMENTED`: required controls are implemented and inspected.
- `TESTED`: named tests passed on a recorded commit and environment.
- `APPROVED`: authorized governance owner recorded approval.

**Fail-closed rule:** absence of evidence is never a PASS. A file, workflow definition, architecture diagram, or test script alone does not prove execution or compliance.

## Evidence contract

Every evaluation record must identify:
1. Repository and exact path or workflow.
2. Branch and full commit SHA.
3. GitHub Actions workflow run ID and job where applicable.
4. Artifact name, immutable URL, and SHA-256 where applicable.
5. Test command, environment, timestamp, result, and scope.
6. Reviewer identity, decision, and approval reference.

## Governance boundaries

- This registry installation does not implement or certify the six SDLC domains.
- Do not infer a license: retain `NOT_VERIFIED` until the repository license file and applicable license text are checked.
- Do not infer maintenance health: record recent commit/release/issue evidence before assigning a maintenance status.
- Do not claim candidate evaluation or runtime PASS without retained execution evidence.
- No application source, database schema, migration, secret, deployment, staging resource, or production configuration is changed by this registry package.
- No merge or deployment is authorized by this PR. Human review and manual merge are required.

## Change control

Changes to schema, scope, status definitions, or domain taxonomy require a versioned registry update and reconciliation across all 27 distributed copies.
